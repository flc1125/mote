# Mote：把 Markdown 变成可分享的网页

写完一份技术方案，或让 AI 整理出一篇调研报告之后，常常还剩下一件事：怎样把它交给别人阅读？直接发 Markdown 文件，接收者需要合适的阅读工具；复制到聊天窗口，长文和图片又不方便浏览。

Mote 为这个环节提供了一条简短的路径：提交 Markdown，获得一个能在浏览器中打开的链接。它面向开发者和 AI Agent 使用者，把写作与分享连接起来，让文档沿用熟悉的 Markdown 格式，读者则直接打开网页。

## 1. 从写好的文档到可阅读的链接

Mote 适合分享已经形成一个版本的内容，例如技术方案、项目介绍、调研报告和会议纪要。作者在编辑器中完成文档，发布之后，将链接交给读者即可。

这也适合 AI 工作流：Agent 完成分析后，可以把结果发布为网页，在对话中返回链接。长篇内容有了独立的阅读页面，后续讨论也能指向同一份已发布的材料。

阅读页面提供标题目录、段落、列表、表格、代码块和图片排版，并随系统偏好切换明暗主题。页面不依赖 JavaScript，阅读主要围绕文档本身展开。

## 2. 一次发布会发生什么

在 CLI 已安装、发布凭证已配置的前提下，发布本地文件只需：

```bash
mote report.md
```

CLI 读取文档，识别 Markdown 引用的本地图片，将它们与正文一起上传。它只处理文档实际引用的图片；同一次发布中，内容相同的图片会合并上传，即使文件名不同也能去重。

服务端为文档生成随机标识，保存完成后返回 URL。读者打开链接时，阅读端把 Markdown 渲染为网页，并将本地图片引用指向已经上传的资源。

远程图片则保留原有地址，仍由原来的图片服务提供。因此，随文上传的本地图片与外部图片，在后续可用性上有所区别。

## 3. 为什么每次发布都生成新链接

Mote 把每次发布视为一份独立的文档快照。修改本地文件后再次发布，会得到新的 URL；已经发出的链接仍对应原先发布的内容。当前没有面向用户的更新或删除接口。

这种方式方便确认讨论所依据的版本。例如，方案经过修改后，可以同时保留评审前后的两条链接。它也意味着作者需要主动把新链接交给读者，旧页面不会自动变成最新版。

这里的不可变，针对的是已发布的 Markdown 和随文上传的资源。阅读页面的样式可能随服务升级变化；引用的远程图片也可能由第三方修改。

访问方式同样直接：**任何知道文档链接的人都可以阅读，无需登录。** 链接包含随机生成的 16 字符 Base58 标识，约有 94 bit 随机熵，用来降低被猜中的可能性；服务本身不提供文档列表或搜索入口。

页面还声明了禁止搜索引擎收录的规则，但这不能代替身份认证。转发链接也就转交了阅读能力。需要指定人员访问、撤销访问权或存放机密信息的场景，需要更强的权限机制。

## 4. CLI、MCP 与 Skill 如何分工

Mote 提供几个入口，适应不同的内容来源：

| 入口       | 适合的工作方式                   | 能力                                                          |
| ---------- | -------------------------------- | ------------------------------------------------------------- |
| CLI        | 作者发布本地文件，或脚本交付报告 | 自动处理本地图片；可用 `--json` 返回文档 ID 和 URL            |
| 远程 MCP   | Agent 发布刚生成的 Markdown      | 提供 `publish_markdown`，接收正文并返回链接；图片使用远程地址 |
| 本地 MCP   | Agent 需要读取本机文档           | 另提供 `publish_markdown_file`，支持本地文件和图片上传        |
| Mote Skill | 教 Agent 识别发布意图并选择入口  | 指导调用已有 CLI 或 MCP 工具                                  |

Skill 是操作说明，实际发布仍需要可用的 CLI 或 MCP 连接，以及对应实例的发布凭证。

例如，用户让 Agent“整理这次调研并发成链接”，Agent 可以先生成 Markdown，再调用远程 MCP 发布。若材料已经保存在本地并包含截图，则可通过 CLI 或本地 MCP 完成。

## 5. 背后的架构

Mote 使用两个 Cloudflare Worker 和一个 R2 存储桶，分别承担发布、阅读和持久化存储。当前架构不引入数据库，也无需维护独立服务器。

发布端负责验证凭证、检查文档与图片，并将正文、资源和元数据写入 R2。阅读端负责根据文档标识读取内容，渲染 HTML；响应可由 Cloudflare 缓存复用。

R2 保存的是 Markdown 源文档和资源，HTML 按需生成。这样的组织方式保留了内容源文件，也让阅读样式能够独立演进。

为避免读者看到上传到一半的文档，服务端最后才写入资源清单 `manifest.json`。阅读端以这份清单判断文档是否发布完成，清单出现前，已上传的部分内容不会对外展示。

渲染时关闭原始 HTML，并通过内容安全策略禁止页面脚本执行，让发布内容保持为文档。

## 6. 使用边界与开始入口

Mote 适合分享一个确定版本的材料，尤其是希望让别人直接阅读的 Markdown 文档和 AI 输出。它目前没有多人编辑、账号权限管理和文档检索能力；需要持续维护同一链接下的内容时，也应先考虑它的不可变设计。

当前上传限制如下，大小按 1024 进制计算：

| 项目          | 限制                       |
| ------------- | -------------------------- |
| Markdown 正文 | 最大 2 MiB                 |
| 单张图片      | 最大 10 MiB                |
| 整个文档包    | 最大 20 MiB                |
| 上传图片数量  | 最多 50 张                 |
| 上传图片格式  | PNG、JPEG、WebP、GIF、AVIF |

SVG 不在支持范围内。使用远程 MCP 发布正文时，无法替你读取本机图片；带本地图片的材料应选择 CLI 或本地 MCP。

项目采用 MIT 许可证，并提供自托管文档。你可以在自己的 Cloudflare 环境部署实例，使用自己的域名、存储与发布凭证。

从现有 Markdown 文件开始，可以阅读 [CLI 使用文档](https://github.com/flc1125/mote/blob/main/docs/cli.md)；让 Agent 直接交付网页，可参考 [MCP 指南](https://github.com/flc1125/mote/blob/main/docs/mcp.md)和 [Skill 说明](https://github.com/flc1125/mote/blob/main/docs/skill.md)。需要自己的实例时，参照[中文自托管指南](https://github.com/flc1125/mote/blob/main/docs/zh-CN/self-hosting.md)。

项目源码与完整文档见 [GitHub：flc1125/mote](https://github.com/flc1125/mote)。
